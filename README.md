# lawmatic-property-division

Открытая спецификация модуля **«Раздел общего имущества супругов»** для систем учёта юридических дел: единая модель данных, движок расчётов и тест‑векторы, которые обязаны проходить все реализации.

Используется в [LawMatic Divorce](https://github.com/SergeiKriukov/LawMatic-Divorce-swiftUI) (macOS/iOS, SwiftUI) и во вкладке «Раздел имущества» веб‑CRM [Legalic](https://legalic.ru). Один и тот же JSON‑документ хранится в файле `.divorce` и в карточке дела Legalic, поэтому данные переносятся между ними без преобразований.

Статус: **черновик 2.0.0‑alpha**. Схема и формулы могут меняться до релиза 2.0.0.

## Что внутри

| Путь | Содержимое |
|---|---|

| [`schema/marital-property.v2.schema.json`](schema/marital-property.v2.schema.json) | JSON Schema документа дела (факты брака, активы, обязательства, сценарии, судебное дело) |

| [`vectors/`](vectors/) | Тест‑векторы «вход → ожидаемый результат»: раздел, госпошлина; далее — цена иска, сроки, подсудность, предупреждения |

## Почему отдельная спецификация

Раздел имущества — это не таблица «объект → стоимость → кому». Юридически корректный расчёт учитывает дату фактического прекращения отношений, личные вложения и маткапитал, отчуждённое без согласия имущество, презумпцию личного характера долгов и их пропорциональное распределение, множество оценок одного объекта, отступление от равенства долей, цену иска по ст. 91 ГПК РФ и прогрессивную шкалу пошлины. Когда такой расчёт реализован дважды (веб и нативное приложение), он неизбежно расходится. Спецификация с общими тест‑векторами — единственный надёжный способ этого избежать.

Модель сущностей нейтральна к юрисдикции (позиции сторон, список оценок, сценарии), расчётный режим задаётся полем `regime`; в v2 реализован только российский законный режим совместной собственности.

## Как использовать

**Валидация документа** (любой инструмент JSON Schema draft 2020‑12), например:

```bash
npx --yes ajv-cli@5 validate --spec=draft2020 -s schema/marital-property.v2.schema.json -d my-case.json
```

**Проверка векторов** (то же, что делает CI):

```bash
npx --yes ajv-cli@5 validate --spec=draft2020 -s schema/vector.schema.json -r schema/marital-property.v2.schema.json -d "vectors/**/*.json"
```

**Реализация движка**: прочитать `SPEC.md` § 4, реализовать функции над документом, прогнать все файлы из `vectors/` (допуск 0,01 ₽). Референсные реализации появятся в `engines/ts` (npm‑пакет) и `engines/swift` (SwiftPM‑пакет `DivorceCore`).

## Правила репозитория

- Репозиторий публичный: **никаких персональных данных**. Векторы из реальных дел — только обезличенные (без ФИО, адресов, кадастровых номеров, VIN, номеров дел).
- Каждое изменение формулы или схемы сопровождается вектором.
- Вектор со статусом `confirmed` подтверждён практикующим юристом или официальным калькулятором; в релиз входят только такие.
- Реквизиты судебной практики перед включением в подсказки интерфейса перепроверяются в СПС.
